When writing code, it is important not to waste time and memory rewriting the same code. This is where classes are helpful. A class is created to package up a set of tasks that can then be repeated throughout the code. Then an object is used to make a small adjustment to the code that is unique and less repetitive than the code inside the class. 

Conceptually, the difference between an object and a class is that an object is a value that can be infinitely asked to complete different tasks. With classes, a set of objects with similar behaviors are packaged together to be called upon later in code. While objects can be infinitely created from a single class, a class can only be declared once within the coding project. The class is responsible for defining what data types and information are used, but the object is where unique information and values are stored.  

What helped me have that ah-ha moment, where the concepts were easier to understand, was realizing that classes are like the blueprints for a house in a track-home neighborhood. Each house was created with the same blueprint, but, just like an object, there may be some changes on top of the original blueprint, such as the shingles' color or the paint color. The objects are added to complement the class but not change it, they add to the house without taking away the core blueprint that is needed to build the house. This is what you will see in my example: the blueprint is the class, and each individual house is the object. Each house has the same blueprint (class), but we use objects to change the details that enable each house to have the same overall structure, but also its own uniqueness.
